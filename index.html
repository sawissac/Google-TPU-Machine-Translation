01 · The Architectural Problem

Why CPUs Cannot Scale for Neural Translation

Von Neumann Bottleneck

CPUs fetch instructions and data through a shared bus. NMT inference needs ~10¹¹ MAC operations per sentence — every MAC demands a memory fetch. The bus saturates completely.

NMT Workload Profile

  • ~90% of compute = matrix multiply
  • Weights are static during inference
  • No data-dependent branching
  • Latency target: <1ms per sentence
  • INT8 precision sufficient

The Scale Problem

200M daily Translate users × 10⁸ MACs/token = 2×10¹⁷ MACs/day — economically impossible on CPU infrastructure.

02 · Neural Network Architecture

Transformer Network — Hardware-Level View

The MAC Operation

Every layer computes y = W·x + b. Expanded form:

yi = Σj  Wij  ·  xj  +  bi
Wij = weight xj = input bi = bias Σ = sum over all j

Each output neuron i multiplies every input xj by its weight Wij, accumulates the products, then adds bias. That single pass = one MAC (Multiply-Accumulate).

Hidden size 512 → 512 × 512 = 262,144 MACs per token per layer. Transformer with 12 layers × 512 tokens = ~1.6 billion MACs per forward pass.

Why It's Hardware-Friendly

  • Weight matrix is read-only at inference
  • No data-dependent branching
  • Fully pipelineable pattern
  • FP32 training → INT8 inference
  • All ops reduce to: acc += a × b

03 · Core Hardware Design

The Systolic Array — Eliminating the Memory Bottleneck

What Is a Systolic Array?

A 2D grid of Processing Elements (PEs). Data pulses like a heartbeat. Weights are pre-loaded and stationary — only activations stream through. Zero memory-bus round-trips between MACs.

TPU v1 MXU: 256 × 256

  • Grid: 256 rows × 256 cols of PEs
  • Each PE: acc += weight × activation
  • MACs/cycle: 65,536 simultaneously
  • Activations flow right →, partial sums ↓
  • Clock: ~700 MHz → 92 TOPS peak

① Unified Buffer — No DRAM Stalls

28 MB on-chip SRAM stores all layer activations. While the MXU computes, data never leaves the chip. DRAM is only accessed between layers.

② Systolic Array — Data Flows Like Waves

Each PE (processing element) multiplies and passes its result to the next — like dominoes. No memory reads between steps. Maximally efficient at 65,536 ops/cycle.

③ CISC ISA — One Instruction, Millions of Ops

A single MatMul macro-instruction fires all 65,536 MACs in parallel. The CPU issues very few instructions. Minimal control overhead.

④ Activation Pipe — INT8 Output

After accumulation in INT32, the activation pipeline applies the non-linearity and requantizes back to INT8 for the next layer — keeping everything tight and fast.

06 · Architectural Evolution

TPU v1 → Trillium: Each Generation Driven by Scale

v1 Specs

  • Peak: 92 TOPS (INT8)
  • Memory: 28 MB SRAM + 8 GB DRAM
  • Precision: INT8 only
  • Mode: Inference only
  • Power: ~75 W · PCIe x16

Design Rationale

Built for GNMT inference latency. INT8 quantization preserved quality. No backprop — keeps chip simple. Built in just 15 months by a small team.

v2 Specs

  • Peak: 180 TFLOPS
  • Memory: 8 GB HBM
  • Precision: BF16/FP32
  • Mode: Train + Inference
  • New: ICI inter-chip link

BF16 Innovation

Google invented Brain Float 16 — FP32 exponent range with 7-bit mantissa. Avoids NaN during backprop at half FP32 memory. Now an industry standard.

v3 Specs

  • Peak: 420 TFLOPS/chip
  • Memory: 32 GB HBM
  • Pod: 1,024 chips = 100+ PFLOPS
  • New: Liquid cooling

Pod Scale

Scaling laws → bigger models = better NMT. v3 Pods trained 100B+ parameter multilingual models enabling zero-shot translation between unseen language pairs.

v4 Specs

  • Peak: 275 TFLOPS/chip
  • Memory: 32 GB HBM
  • Pod: 4,096 chips
  • Topology: 3D torus — 6 ICI links/chip

3D Torus Network

Each chip connects to 6 neighbors in 3D torus. Minimizes all-reduce latency across 4,096 chips. Topology co-designed with model parallelism. Powers Gemini, Bard.

v5e Specs

  • Peak: 197 TFLOPS/chip (BF16)
  • Memory: 16 GB HBM2e · 819 GB/s bandwidth
  • Precision: BF16, INT8, FP8
  • Pod: 256 chips per slice
  • Mode: Train + Inference · best perf/$ in fleet

LLM-Era Design

v5e targets cost-efficient LLM serving — FP8 halves memory vs BF16, doubling effective throughput for transformer inference. Pod topology redesigned for tensor-parallel and pipeline-parallel workloads needed by 100B+ parameter models like PaLM 2.

Trillium (v6e) Specs

  • Compute: 4.7× v5e per chip
  • Memory BW: 2× v5e
  • Energy efficiency: 3× v5e
  • Precision: BF16, INT8, FP8, INT4
  • ICI: 2× bandwidth for larger pods

Gemini Era

Trillium is Google's 6th-gen TPU, announced at Google Cloud Next 2024. Built for Gemini-scale multimodal training. INT4 support cuts memory 8× vs FP32 — critical for fitting trillion-parameter models in a pod. 3× energy gain directly reduces cost-per-token, making frontier inference economically viable at Google scale.

Systolic array eliminates the von Neumann bottleneck
65,536 MACs fire simultaneously. Weights stay in PEs — zero bus round-trips. Memory-bandwidth-bound workload becomes compute-bound.

Hardware–software co-design is essential
INT8 quantization matched exactly to the MXU. GNMT and TPU designed together — neither works optimally alone.
03
Domain-specific silicon dominates at scale
83× perf/watt vs CPU, 75W vs 200W GPU for same NMT task. Economic case is decisive at 500M-user scale.
